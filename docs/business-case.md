# Cas métier — Dashboard décisionnel de pilotage

## Contexte

Une organisation pilote un programme déployé sur plusieurs zones géographiques. Chaque mois, elle doit suivre :

- les activités planifiées et effectivement réalisées ;
- le nombre de bénéficiaires atteints ;
- les responsables impliqués ;
- le budget prévu et le budget consommé ;
- les écarts importants ;
- la qualité du reporting.

## Le problème

Les données existent, mais elles sont souvent :

- dispersées entre plusieurs fichiers Excel ;
- consolidées manuellement ;
- lues trop tardivement pour être exploitables ;
- insuffisamment structurées pour aider à la décision.

Le décideur ne manque pas de données.
Il manque de **lecture claire, hiérarchisée et orientée action**.

## Ce que le dashboard résout

Le tableau de bord permet à un dirigeant de :

- piloter les réunions mensuelles avec des données à jour ;
- repérer les contre-performances par zone ;
- identifier les zones prioritaires ;
- arbitrer les actions correctives ;
- vérifier la cohérence entre exécution et dépense.

## Pourquoi ce cas est pertinent

Ce scénario est :

- **crédible** : il correspond à des situations réelles dans de nombreuses organisations ;
- **universel** : transposable à des ONG, PME, institutions, programmes ;
- **riche** : il couvre activités, bénéficiaires, budget, reporting et alertes ;
- **lisible** : intelligible pour un décideur non-technicien ;
- **réutilisable** : adaptable à d'autres secteurs sans refonte.

## Ce que cette démonstration ne prétend pas

- Elle ne présente aucun client réel.
- Elle ne contient aucune donnée réelle.
- Elle ne prétend pas qu'un dashboard seul résout tous les problèmes de pilotage.
- Elle montre une **méthode**, une **logique de restitution** et un **niveau d'exécution**.
